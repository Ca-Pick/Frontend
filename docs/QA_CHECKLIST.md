# QA 체크리스트

> ⚠️ **실제 라우트 구조 (명세서와 다른 부분)**
> 코드 기준 실제 라우팅은 아래와 같습니다. 이하 체크리스트의 URL은 명세서 표기를 그대로 두되, 실 테스트 시 아래 실제 경로 기준으로 진행하세요.
> - 홈: `/` (명세서: `/home`)
> - 검색/주문서 5단계: `/order/*` (내부 스텝 상태로 관리, 명세서의 `/search/step1-region` 등 별도 라우트 아님)
> - 레퍼런스(케이크) 상세: `/desserts/:cakeId` 및 `/order` 내부 detail 상태 두 종류 존재 (명세서: `/reference/{id}`)
> - 저장함: `/saved`, 마이페이지: `/mypage`, 로그인: `/login`
> - 정의되지 않은 경로는 전부 `/`(홈)으로 리다이렉트됨 — 이용약관/개인정보처리방침이 별도 페이지 라우트인지, 외부 링크인지 실제 구현 확인 필요

## 1. 홈 화면 (`/`)
UI
- [ ] 헤더 좌측 로고 노출 확인
- [ ] "어떤 케이크를 찾고 있나요?" 문구 + "주문하기" 버튼 노출
- [ ] 추천 레퍼런스 캐러셀 정상 렌더링 (이미지, 태그, 저장 하트)
- [ ] 캐러셀 하단 인디케이터(dots) 표시 및 현재 슬라이드 표시 일치
- [ ] 태그 3~5개 노출, 초과 시 "+n" 표시 확인
- [ ] Bottom Navigation 4개 탭(홈/검색/저장/마이) 아이콘·라벨 정상 표시, 홈 탭 활성화 스타일

기능
- [ ] 로고 클릭 시 최상단으로 스크롤
- [ ] "주문하기" 클릭 시 검색/주문서 플로우(`/order`)로 이동
- [ ] 캐러셀 좌우 스와이프 동작
- [ ] 캐러셀 화살표 클릭으로 슬라이드 이동
- [ ] 인디케이터 점 클릭 시 해당 슬라이드로 이동
- [ ] 저장 버튼 클릭 — 비로그인 시 로그인 페이지로 이동
- [ ] 저장 버튼 클릭 — 로그인 상태에서 저장/해제 토글 (하트 채움/비움)
- [ ] 저장 버튼: 낙관적 업데이트로 UI 즉시 반영되는지 확인
- [ ] 저장 API 실패 시 상태 롤백 확인 (네트워크 차단 등으로 강제 실패 재현)
- [ ] Bottom Navigation 각 탭 클릭 시 올바른 라우트(`/`, `/order`, `/saved`, `/mypage` or `/login`)로 이동
- [ ] '마이' 탭: 로그인 여부에 따라 `/mypage` 또는 `/login` 분기 확인
- [ ] **[회귀] 로그인 후 홈으로 리다이렉트되기 전, 비로그인 상태의 홈 콘텐츠가 한 프레임이라도 깜빡이며 노출되지 않는지 확인** (과거 버그: 리다이렉트 직전 홈이 잠깐 보였다가 사라짐 → 스피너로 가리는 처리로 수정됨, 회귀 여부 재확인)
- [ ] **[회귀] 로그인 직후 홈 진입 시 하트가 "즉시 채워진 상태"로 보이는지 확인** (savedCakes 캐시 갱신 타이밍 이슈 이력 있음)
- [ ] **[회귀] 홈 추천 목록 API가 로그인 상태에서 쿠키 포함 요청(authClient)으로 나가는지 확인** — 비인증 클라이언트(publicClient)로 나갈 경우 로그인 상태여도 `saved` 필드가 항상 false로 내려와 하트가 전부 비어 보이는 버그 이력 있음. 해당 요청 실패 시 publicClient로 폴백되는지도 함께 확인

API / 데이터
- [ ] `GET /api/v1/references/recommendations?limit=10&offset=0` 정상 응답 확인
- [ ] `hasMore: true`일 때 추가 로드(페이지네이션/무한스크롤) 동작 확인
- [ ] `POST /api/v1/references/{id}/save`, `DELETE /api/v1/references/{id}/save` 헤더에 `Authorization: Bearer {token}` 포함 확인
- [ ] TanStack Query 캐시 TTL(5분) 이후 재요청 발생 확인
- [ ] **[회귀] 저장함(useSavedCakes)이 자동 refetch가 꺼진 상태(저장함 탭에 진입하지 않은 세션)에서도, 홈/상세/검색결과 등 다른 화면에서 저장·해제한 결과가 캐시에 즉시 반영되는지 확인** (setSavedCakeInCache 헬퍼로 수동 동기화하던 이력 — 화면 간 하트 상태 불일치 가능성 재검증)

에러 처리
- [ ] 401 응답 시 로그인 페이지로 리다이렉트
- [ ] API 실패 시 토스트 에러 메시지 노출 + 저장 상태 롤백
- [ ] 네트워크 오류 시 재시도 버튼 노출 및 동작
- [ ] **[회귀] 저장(좋아요) 버튼 클릭 시 401 인터셉터의 하드 리다이렉트와 하트 버튼 자체의 로그인 이동 로직이 중복 실행되지 않는지 확인** (과거: 두 로직이 동시에 발동해 이동이 중복/꼬이던 버그 → saveCake/unsaveCake에 skipAuthRedirect 적용으로 수정)

접근성
- [ ] 이미지 alt 텍스트 존재
- [ ] 아이콘 버튼(하트, 화살표 등) aria-label 존재
- [ ] 현재 탭에 `aria-current="page"` 적용
- [ ] 키보드만으로 캐러셀/탭 이동 가능 여부

## 2. 로그인 페이지 (`/login`)
UI
- [ ] 서비스 로고 화면 상단 중앙 노출
- [ ] 로고 미로딩 시 대체 이미지 표시
- [ ] 카카오/네이버 버튼 레이아웃 (로고 → 카카오 → 네이버 순서) 확인

기능 - 버튼 문구 분기
- [ ] 기존 회원 로그인 시 "카카오톡으로 시작하기" / "네이버로 시작하기" 문구
- [ ] 신규 회원(회원가입) 시 "카카오톡으로 계속하기" / "네이버로 계속하기" 문구

기능 - 인증 플로우
- [ ] 카카오 버튼 클릭 → 카카오 인증 화면 이동
- [ ] 네이버 버튼 클릭 → 네이버 인증 화면 이동
- [ ] 인증 성공 + 기존 회원 → 홈 또는 직전 화면 이동
- [ ] 인증 성공 + 신규 회원 → 회원가입 완료 후 홈 화면 이동
- [ ] 인증 실패/취소 → 현재 화면 유지 + 토스트 "카카오(네이버) 로그인이 취소되었어요. 다시 시도해주세요."
- [ ] `redirect` 쿼리 파라미터 있을 시 로그인 후 해당 경로로 이동 (예: `/login?redirect=/search/results`)
- [ ] `redirect` 파라미터 없을 시 `/home`으로 이동
- [ ] **[회귀] 로그인 화면에서 "뒤로가기" 시 진입 경로별 분기 확인**: 검색/주문서(`/order`) 또는 상세 화면에서 로그인으로 넘어온 경우 해당 화면으로 복귀, 홈/큐레이션/저장함/마이페이지에서 온 경우 홈으로 이동 (과거: 모든 경우 무조건 홈으로만 이동하던 버그)
- [ ] **[회귀] 검색 스텝(1~5) 진행 중 로그인으로 이탈 후 복귀 시, 이전에 선택했던 지역/대상/형태/색감/분위기/장식 값이 그대로 복원되는지 확인** (URL 쿼리에 검색 상태 보존)
- [ ] **[회귀] 상세 화면(`/desserts/:cakeId` 또는 주문서 내 상세)에서 로그인 후 복귀 시, 상세 화면인데도 하단 탭(BottomTabNavigation)이 잘못 노출되지 않는지 확인** (과거: view가 'detail'로 상태 복원될 때 onDetailViewChange 미호출로 하단탭이 그대로 보이던 버그)
- [ ] **[회귀] 소셜 로그인 시작 시 redirect_uri가 현재 접속 중인 프론트엔드 origin(`window.location.origin`)으로 정확히 전달되는지 확인** — 로컬 개발환경과 배포환경(Vercel 등) 각각에서 로그인 후 원래 접속했던 주소로 정상 복귀하는지 재검증 (과거: origin이 하드코딩되어 있어 환경이 꼬이던 이력)

API
- [ ] `POST /api/v1/auth/social-login` 요청 바디(provider, accessToken, idToken) 정상 전달
- [ ] 200 응답(`isNewUser: false`) 케이스 처리
- [ ] 201 응답(`isNewUser: true`) 케이스 처리
- [ ] 400 `AUTH_FAILED` 응답 처리
- [ ] 로그인 요청 시 `withCredentials: true` 설정 확인
- [ ] Refresh Token이 httpOnly 쿠키로 저장되는지 확인 (JS에서 접근 불가해야 함)
- [ ] Access Token이 메모리에만 저장되고 로컬스토리지 등에 남지 않는지 확인
- [ ] **[회귀] 로그인 상태 판별에 사용하는 쿠키 이름이 백엔드 실제 쿠키명(`accessToken`)과 정확히 일치하는지 확인** (과거: 프론트에서 `access_token`으로 파싱해 로그인 상태를 오판하던 버그)
- [ ] **[회귀] `getCookie`/`isLoggedIn` 유틸 기준으로 하트 버튼 등 UI 전반의 로그인 상태 판정이 일관되는지 확인** (과거: 화면별로 로그인 판정 로직이 달라 하트 버튼 등에서 상태 불일치 발생)

에러 처리
- [ ] 네트워크 오류 시 "네트워크 연결을 확인해주세요." 노출
- [ ] 서버 오류 시 "일시적 오류가 발생했습니다. 다시 시도해주세요." 노출
- [ ] 로딩 중(isLoading) 버튼 중복 클릭 방지 확인

배포 환경
- [ ] **[회귀] 배포 환경(Vercel)에서 `/login` 등 하위 경로를 새로고침하거나 URL로 직접 접근했을 때 404가 뜨지 않는지 확인** (과거: SPA rewrite 설정 누락으로 404 발생 → vercel rewrite 설정 추가로 수정. `/order`, `/saved`, `/mypage`, `/desserts/:id` 등 모든 하위 경로 동일하게 재검증)

## 3. 마이페이지 (`/mypage`)
UI
- [ ] 프로필 이미지(기본/업로드) 정상 노출
- [ ] 닉네임, 이메일 프로필 이미지 하단 표시
- [ ] 이메일은 읽기 전용(클릭 동작 없음) 확인
- [ ] **[회귀] 이메일 대신 소셜 로그인 제공자(카카오/네이버)가 표시되는 UI로 변경되었는지 확인 — 명세서(이메일 표시)와 실제 구현이 다를 수 있음, 실제 화면 기준 재검증**
- [ ] 메뉴 섹션: 고객센터(라벨, 비버튼), 이용약관(버튼), 개인정보처리방침(버튼)
- [ ] 계정 관리 섹션: 로그아웃, 회원탈퇴(빨간색 강조) 버튼

기능
- [ ] `/mypage` 직접 접근 시 비로그인 상태면 로그인 페이지로 이동 (ProtectedRoute 적용 확인)
- [ ] 고객센터 항목 클릭 시 아무 동작 없음(MVP 범위) 확인
- [ ] 이용약관 클릭 시 약관 화면/외부 링크 이동
- [ ] 개인정보처리방침 클릭 시 해당 화면/외부 링크 이동
- [ ] 로그아웃 클릭 → "로그아웃하시겠어요?" 확인 팝업 노출
  - [ ] 취소 시 팝업만 닫히고 마이페이지 유지
  - [ ] 확인 시 로그아웃 처리 후 홈/로그인 화면 이동
- [ ] 회원탈퇴 클릭 → "정말 탈퇴하시겠어요? / 저장한 모든 데이터가 삭제됩니다" 팝업 노출
  - [ ] 취소 시 팝업만 닫히고 마이페이지 유지
  - [ ] 확인 시 탈퇴 처리 후 로그인 화면 이동
  - [ ] 탈퇴 후 저장한 케이크/가게 목록, 계정 정보, 로그인 토큰 모두 삭제되는지 확인
  - [ ] **[회귀] 탈퇴 완료 후 홈으로 이동하며 "회원탈퇴가 완료되었습니다" 안내 스낵바가 노출되는지 확인**
- [ ] **[회귀] 로그아웃/회원탈퇴 시 `savedCakes` 쿼리 캐시가 완전히 제거되는지 확인** (과거: 캐시가 남아있어 로그아웃 후에도 하트가 채워진 채로 보이던 버그)
- [ ] **[회귀] 로그아웃/회원탈퇴 시 주문서(`/order`) 작성 상태를 담고 있는 `sessionStorage`(`orderLastPath` 등)도 함께 초기화되는지 확인** — 초기화되지 않으면 다른 계정으로 재로그인 후에도 이전 세션의 주문서 진행 상태(스텝/선택값)가 그대로 복원될 수 있음
- [ ] **[회귀] 로그아웃 시 불필요한 토큰 재발급 요청이 발생하지 않는지 확인** (authState로 로그아웃 상태 추적)

API
- [ ] `GET /api/v1/user/profile` 정상 응답 및 렌더링
- [ ] `POST /api/v1/auth/logout` 정상 동작
- [ ] `DELETE /api/v1/user/account` 정상 동작
- [ ] 각 요청에 `Authorization: Bearer {token}` 헤더 포함 확인

에러 처리
- [ ] 프로필 로드 실패 시 "사용자 정보를 불러올 수 없습니다." 노출
- [ ] 로그아웃 실패 시 "로그아웃에 실패했습니다. 다시 시도해주세요." 노출
- [ ] 회원탈퇴 실패 시 "회원탈퇴에 실패했습니다. 다시 시도해주세요." 노출
- [ ] 네트워크 오류 시 공통 메시지 노출

접근성
- [ ] 모달에 `role="dialog"`, `aria-modal="true"` 적용
- [ ] 버튼 aria-label 존재
- [ ] 회원탈퇴 버튼 시각적 위험 표시(빨간색) 확인

## 4. 저장함 페이지 (`/saved`)
UI
- [ ] 타이틀 "저장함" 상단 노출
- [ ] 카테고리 탭(케이크/가게) 노출, 케이크 탭 기본 선택
- [ ] 활성/비활성 탭 색상 구분
- [ ] 정렬 드롭다운 기본값 "최신순" 확인, 옵션(최신순/오래된순/인기순) 노출
- [ ] 케이크 탭: 2열 그리드 카드(이미지, 가게명, 하트) 레이아웃
- [ ] 빈 상태 문구 노출 확인: "저장한 케이크가 없습니다. 마음에 드는 케이크를 저장해보세요."

## 7. API 엔드포인트 상세 테스트

7-1. 인증 (로그인 페이지)
`POST /api/v1/auth/social-login`
- [ ] 요청 바디 `provider`("kakao"/"naver") 값별 정상 동작
- [ ] 요청 바디 `accessToken` 필수, `idToken` 선택값 처리 확인
- [ ] 200 OK 응답 시 `isNewUser: false` + `user{id, email, name}` 필드 매핑
- [ ] 201 Created 응답 시 `isNewUser: true` 케이스에서 회원가입 완료 플로우로 분기
- [ ] 400 `AUTH_FAILED` 응답 시 메시지 노출 및 재시도 가능 상태로 복귀
- [ ] 응답의 `refreshToken`이 httpOnly 쿠키로만 내려오는지 (JS `document.cookie`로 조회 불가해야 함)

## 9. 개발 중 발견된 주요 회귀 포인트 요약 (우선순위 재테스트용)

아래는 실제 개발 과정에서 발견되어 수정된 버그들을 화면 단위가 아닌 "실패 패턴" 단위로 모은 목록입니다. 회귀 테스트 시 우선순위로 확인하세요.

1. **하단 탭 노출 동기화**: view/route가 "복원"되는 모든 시나리오(로그인 리다이렉트 복귀, 뒤로가기, 새로고침)에서 상세 화면 여부와 하단 탭 노출이 항상 일치해야 함. `onDetailViewChange` 같은 상태 변경 콜백이 상태 "복원" 시에도 호출되는지가 핵심.
2. **로그인 왕복 흐름**: 로그인으로 이탈 → 뒤로가기/성공 후 복귀했을 때 "어디서 왔는지"에 따라 복귀 위치가 달라야 함 (검색·상세는 원위치 복귀, 그 외는 홈). 검색 단계 값은 URL 쿼리로 보존되어야 복귀 후에도 동일해야 함.
3. **저장(좋아요) 상태의 이중 관리**: 저장 여부가 (a) 목록 API 응답의 `saved` 필드, (b) TanStack Query의 `savedCakes` 캐시, 두 군데에서 따로 관리되어 화면 간 불일치가 잦았음. 저장/해제 후 모든 화면(홈/상세/저장함/검색결과/캐러셀)에서 동시에 하트 상태가 맞는지 항상 교차 확인.
4. **401 처리 경로 중복**: 인증 만료 시 인터셉터의 전역 리다이렉트와, 개별 컴포넌트(하트 버튼 등)의 로그인 이동 로직이 동시에 걸리지 않아야 함 — 저장 관련 요청뿐 아니라 다른 인증 필요 액션에도 동일한 패턴이 있을 수 있는지 확인.
5. **로그아웃/탈퇴 시 잔존 상태**: Query 캐시(`savedCakes`)뿐 아니라 `sessionStorage`에 남는 주문서 진행 상태까지 초기화 대상에 포함되어야 함. 새로운 로컬/세션 저장 상태를 추가할 때마다 로그아웃·탈퇴 초기화 로직에도 함께 반영되었는지 확인.
6. **falsy-but-invalid ID 처리**: `cakeId`처럼 0이 "없음"을 의미하는 값에서 `!!value` 같은 단순 truthy 체크는 버그를 유발함. 유사한 ID/인덱스 값을 다루는 다른 훅에도 같은 패턴이 있는지 점검.
7. **props vs 재조회**: 상위에서 이미 받은 데이터를 하위 컴포넌트가 다시 API로 조회하는 중복 호출 패턴이 반복적으로 발견됨. 새 컴포넌트 추가 시 필요한 데이터가 이미 상위에 있는지 먼저 확인.
8. **명세서와 실제 구현의 UX 차이**: (a) 라우트 구조(`/order/*`, `/desserts/:id`가 명세서의 개별 라우트와 다름), (b) 지도 SDK(카카오맵 vs 명세서의 구글/네이버맵), (c) "다른 케이크" 선택 시 페이지 이동 대신 바텀시트 프리뷰로 뜨는 점 — QA 시 명세서 문구가 아니라 실제 화면 동작을 기준으로 판단.
9. **주문서 스텝 옵션 누락**: UI 명세에는 있으나 실제 배열/상수에서 누락된 선택지가 발견된 이력(대상 선택지 '서포트', 스텝4 '이전' 버튼). 새 스텝/옵션 추가·변경 시 명세서의 전체 옵션 목록과 실제 배열을 1:1 대조.
10. **초기화(Reset) 플로우 (신규 기능, 현재 작업 중)**: 스텝1 "초기화" 버튼의 노출 조건(`hasStepInput`)과, 초기화 시 지워야 할 상태 범위(스텝, 검색 파라미터, 선택된 카드, 상세 스택, URL 쿼리)가 빠짐없이 리셋되는지 별도로 집중 테스트 필요 — 아직 커밋 전 변경사항이므로 병합 전 최우선 검증 대상.
